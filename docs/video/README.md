# Unmask — матеріали для демо-відео (≤ 3 хв)

## ✅ Відео знято

Опубліковано: https://youtu.be/twOhTTLxAYE

`unmask-demo.mp4` — **2:47.9**, 1920×1080 @ 30 fps, англійська озвучка, −16.4 LUFS (true peak −1.4 dBFS).
Субтитри — `unmask-demo.srt`. Аудіо: 48 kHz stereo AAC-LC 192 kbps; відео: один SPS, `+faststart`. Збирається повністю скриптами з `production/`, вручну нічого не монтувалося.

Що в кадрі справжнє: усі числа — з живої відповіді бота й з `production/api_GnQUsLcy.json` (ризик 72,
2 кластери, #1 = 6 гаманців, share 0.9206, confidence 0.776). Графи — ті самі PNG, що бот шле в чат.
Чат із ботом знятий наживо через CDP :9022; чистий токен справді віддав `risk 0/100 — clean`.

> **Приватність.** Ліва колонка Telegram (список чатів) у кадр не потрапляє: запис кропається по
> середній колонці, `tg.assert_private()` перевіряє розкладку перед кожною сценою, а `qc_privacy.py`
> ще раз сканує вже готове відео. Сирі кадри (в них колонка ще є) лежать у скретчпаді й видаляються
> одразу після кодування.

### Як перезібрати

```bash
cd docs/video/production
python3 tts_segments.py      # ElevenLabs; наявні кліпи не переспівує (ELEVENLABS_API_KEY)
python3 make_durations.py    # durations.json — під ці тривалості знімається екран
python3 slides.py            # slides/*.png; падає, якщо текст виліз за свою панель
python3 capture_tg.py        # живий чат через CDP :9022 → capture/tg.mp4 + scenes.json
python3 assemble_video.py    # → ../unmask-demo.mp4 + ../unmask-demo.srt
python3 qc_privacy.py        # списку чатів у кадрі немає
python3 tts_qc.py . small    # whisper назад на текст
```

Порядок обовʼязковий: `capture_tg.py` читає `durations.json`, тож після будь-якої переспівки спершу
`make_durations.py`, інакше картинка й слова розʼїдуться.

`capture_tg.py` надсилає боту три `/check` наживо. Усі три токени прогріті, тож кеш-хіти не їдять
ліміт (5 нових перевірок / 10 хв), і перезняти можна скільки завгодно разів.

**Граблі, на які вже наступили** (не повторювати):
- темп TTS 0.95 дає 3.2 слова/с — для суддів задихано; 0.85 дає 2.5–2.9 і все одно влазить у 3:00;
- адресу монети треба `Input.insertText`, а не друкувати: 44 символи по CDP = сцена на 1.2 с довша
  за свою озвучку, і асемблер ріже її посеред адреси;
- у премікс-команди `-t` обовʼязковий: музика йде через `-stream_loop -1`, і без обмеження
  ffmpeg пише wav, поки не скінчиться диск (перший раз встиг 25 ГБ);
- однопрохідний `loudnorm` лишає стрибок підсилення на початку — тут він двопрохідний;
- **звук мусить бути 48 kHz stereo ЯВНО**: `amix` бере найвищу частоту серед входів, і майстер
  вийшов 96 kHz **моно** — QuickTime такий файл показує без звуку. `-ar 48000 -ac 2` треба і на
  премікс, і на фінальний mux. Перевірка саме стеком Apple, не ffmpeg:
  `afinfo unmask-demo.mp4` має дати `2 ch, 48000 Hz, aac` і `Channel layout: Stereo (L R)`;
- **усі кліпи мусять кодуватися в ОДНАКОВИЙ SPS**: кадри Telegram ідуть із JPEG і тому
  full-range (`yuvj420p`), слайди — limited. Склейка `-c copy` поклала в одну доріжку два різні
  SPS, тоді як `avcC` оголошує лише перший; ffmpeg і Chrome переналаштовуються на льоту,
  QuickTime — ні. Звідси `VTAIL`/`VFLAGS` і `scale=in_range=full:out_range=tv`;
  перевірка — у готовому файлі рівно ОДИН унікальний SPS;
- whisper на клонованому голосі впевнено пише «болгарську» з sim 0.00: це артефакт детекції,
  перевіряти форсованим `language="en"`, а не вірити мітці (`qc_tts.log`).

## Що це за токени (чесно)

- Це реальні токени з документованого експерименту (README, розділ «Cohort experiment»): запуски початку 2025 року.
  У відео не називайте їх «свіжими» чи «живими запусками»; кажіть «реальні токени».
- Мітки «MELT» у README — цінова/модельна ознака маніпуляції, не підтверджене інсайдерство. Unmask шукає
  фінансові звʼязки (спільне джерело, однакові суми, один слот), це сигнал, а не доказ, і не фінансова порада.
- Профіль аналізу: перші 30 покупців, глибина фінансування 2, 30 підписів на гаманець, без SPL
  (`config/ingest.yaml` v5). Повний профіль із PRD (200–500 покупців) на безкоштовних ключах не завершується; це
  описано в README, розділ «Analysis profile».
- Холодний (не прогрітий) токен рахується приблизно 1–2 хв із повідомленнями про прогрес у боті; потім кеш.

## Для треку RPC Fast

Прогріті токени вище — з початку 2025 року, тож їхню історію віддають архівні провайдери, а RPC Fast майже не бере
участі (він зберігає ≈ 21,5 год історії). Щоб у відео чи в сабміті показати саме роботу RPC Fast, візьміть СВІЖИЙ токен
(створений до ~18 год тому; список зі свіжими, напр. з pump.fun) і виконайте `/check` на ньому: аналіз піде 1–3 хв, а в
логу сервісу (`/tmp/unmask_serve.log` на сервері, рядок `rpc_pool …` раз на хвилину) буде видно `rpcfast requests=… units=…`
з ненульовими числами. Цей кадр логу можна показати в сабміті як доказ використання RPC Fast.

## Правила під час запису

1. Ліміт бота: 5 нових перевірок на 10 хв на користувача. Кеш-хіти квоту не витрачають, тож 4–5 токенів з
   прогрітих — вільно. Не запускайте повторні дублі поспіль зайвий раз.
2. Токен бота й ключі RPC у кадр не потрапляють: у чаті їх немає. Не відкривайте `.env`.
3. Демо-URL API у README ще має заповнити оператор (`<DEMO_URL>`). Для кадру з API використайте
   `http://<IP-сервера>:18080/api/token/<mint>` лише якщо ви готові показати IP; інакше покажіть відповідь у
   терміналі через `curl localhost:18080/...` на сервері.
4. Якщо щось не відповідає (бот мовчить): `curl localhost:18080/healthz` на сервері має дати `200`;
   запасні кадри — у `stills/`.
